# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

FlowSync is a course practice project (team task management). It is a monorepo with two independent npm packages and no root `package.json`:

- `backend/` — AdonisJS 7 JSON API (TypeScript, Lucid ORM, SQLite via better-sqlite3), runs on `http://localhost:3333`
- `frontend/` — React 19 + Vite 8, runs on `http://localhost:5173` (Tailwind v4 + shadcn/ui-style components, `react-router`; login/signup/profile wired to the API via `src/lib/api.ts`, API base from `VITE_API_URL`, see `frontend/.env.example`)

Work happens on the `s1/start` branch. Project docs and commit messages are in Spanish.

## Commands

Run each app in its own terminal, from its own directory.

### Backend (`cd backend`)

```bash
npm install
cp .env.example .env && node ace generate:key   # first-time setup
node ace migration:run                           # also regenerates database/schema.ts
npm run dev          # node ace serve --hmr
npm test             # node ace test (Japa)
node ace test unit   # run one suite (unit | functional)
node ace test --files=tests/functional/auth.spec.ts   # run one file
node ace test --tests="test title"                    # run one test by title
npm run lint         # eslint
npm run typecheck    # tsc --noEmit
npm run format       # prettier
```

### Frontend (`cd frontend`)

```bash
npm install
npm run dev
npm run build        # tsc -b && vite build
npm run lint         # oxlint
```

## Backend architecture

- **Import aliases**: use the `#controllers/*`, `#models/*`, `#validators/*`, `#transformers/*`, `#start/*`, `#config/*`, `#database/*`, `#generated/*` etc. subpath imports defined in `backend/package.json` (with `.js` targets), not relative paths.
- **Generated code (don't edit by hand)**:
  - `database/schema.ts` — Lucid column classes (`UserSchema`, `AuthAccessTokenSchema`) generated from the DB by `node ace migration:run`. Models extend these (e.g. `User extends compose(UserSchema, withAuthFinder(hash))`) rather than declaring columns themselves. Custom type rules go in `database/schema_rules.ts`.
  - `.adonisjs/` — generated by `adonisrc.ts` init hooks (`indexEntities`, Tuyau `generateRegistry`). `.adonisjs/server/controllers.ts` exposes the `controllers` map used in `start/routes.ts` (`[controllers.Profile, 'show']`), so new controllers become available there after the dev server/ace regenerates it. The client registry (`.adonisjs/client`) is exported as `backend/registry` / `backend/data` for typed API clients and is also used to type Japa's api-client routes.
- **Routing**: `start/routes.ts`. API lives under `/api/v1`; `auth/signup` and `auth/login` are public, `account/*` routes use the named `auth` middleware.
- **Auth**: default guard is `api` (opaque access tokens stored in `auth_access_tokens`, issued via `User.accessTokens.create`). A session `web` guard is also configured. `silent_auth_middleware` runs `auth.check()` on every routed request.
- **Responses**: `force_json_response_middleware` forces `Accept: application/json` globally. `providers/api_provider.ts` adds `ctx.serialize()` which wraps payloads in `{ data: ... }` (and handles Lucid pagination meta). Controllers return `serialize(SomeTransformer.transform(model))`; transformers in `app/transformers/` whitelist exposed fields via `this.pick(...)`.
- **Validation**: VineJS validators in `app/validators/`, created with `vine.create(...)` and consumed via `request.validateUsing(...)`.
- **Database**: SQLite file at `backend/tmp/db.sqlite3` (gitignored). Migrations in `database/migrations/`.
- **CORS**: all origins allowed in dev, empty allowlist otherwise (`config/cors.ts`).
- **Tests**: Japa suites `unit` (`tests/unit/**/*.spec.ts`) and `functional` (`tests/functional/**/*.spec.ts`, starts the HTTP server) configured in `adonisrc.ts`; plugins in `tests/bootstrap.ts` include api-client, auth/session api-client helpers and DB assertions. `.env.test` sets `SESSION_DRIVER=memory`. No test files exist yet.

## Reglas de proceso
- Antes de tocar código: crear una rama nueva (`git checkout -b feat/<slug>`). Nunca commitear directo en `main`/`s1/start`.
- Al cerrar la tarea: usar la skill `/commit`, luego `gh pr create` con una descripción completa de los cambios en el cuerpo del PR.
- Después de abrir el PR: usar el subagente `adversarial-reviewer` sobre él, antes de darlo por terminado.
- No repitas ese resumen en el chat: la sesión se va a perder, el PR no. Responde solo con la URL del PR.
