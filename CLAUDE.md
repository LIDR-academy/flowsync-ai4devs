This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

FlowSync is a practice project for team task management (course exercise). It's a monorepo with two independent apps that are not currently wired together beyond CORS:

- `backend/` — API in AdonisJS 7, TypeScript, SQLite (via `better-sqlite3`)
- `frontend/` — React 19 + Vite, currently the unmodified Vite scaffold (no routing/data-fetching wired up yet)

Current branch `s1/start` represents an early foundational state: auth (signup/login/logout/profile) is implemented on the backend; the frontend has not yet been built out to consume the API.

## Commands

### Backend (`backend/`)

```bash
cd backend
npm install
cp .env.example .env
node ace generate:key      # populates APP_KEY in .env
node ace migration:run
npm run dev                # serves with HMR at http://localhost:3333
```

- `npm run test` — runs Japa test suites (`node ace test`)
- `npm run lint` — eslint
- `npm run format` — prettier --write
- `npm run typecheck` — tsc --noEmit
- `npm run build` — `node ace build`
- Run a single test file: `node ace test <path/to/file.spec.ts>` (Japa supports filtering; see `node ace test --help`)
- Ace commands in general: `node ace <command>` (e.g. `node ace make:controller`, `node ace make:migration`, `node ace migration:rollback`)

### Frontend (`frontend/`)

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
```

- `npm run build` — `tsc -b && vite build`
- `npm run lint` — oxlint
- `npm run preview` — preview production build

Run backend and frontend in separate terminals; the frontend expects the API at `http://localhost:3333` (see CORS config).

## Architecture

### Backend: AdonisJS 7 conventions

- **Path aliases** (subpath imports, defined in `backend/package.json` `imports`): `#controllers/*`, `#models/*`, `#validators/*`, `#transformers/*`, `#middleware/*`, `#database/*`, `#services/*`, `#events/*`, `#listeners/*`, `#policies/*`, `#abilities/*`, `#providers/*`, `#start/*`, `#config/*`, `#tests/*`, `#generated/*` (maps to `.adonisjs/server/*`, code generated at build/dev time — don't hand-edit).
- **Routing**: `backend/start/routes.ts` defines routes using `controllers` imported from `#generated/controllers` (auto-generated registry from `@tuyau/core`, not manual controller imports). All API routes are grouped under `/api/v1`. Auth-protected routes use `.use(middleware.auth())` defined via named middleware in `backend/start/kernel.ts`.
- **Middleware pipeline** (`backend/start/kernel.ts`): server-level middleware (force JSON response, container bindings, CORS) runs on all requests; router-level middleware (bodyparser, session, shield, auth initialization, silent auth) runs on routed requests. `silent_auth_middleware` checks auth without blocking; `auth_middleware` (named `auth`) is applied per-route/group to actually require authentication.
- **Auth** (`backend/config/auth.ts`): two guards — `api` (token-based, `DbAccessTokensProvider`, default guard for stateless API auth) and `web` (session-based). Access tokens are managed via `User.accessTokens` (see `app/models/user.ts`).
- **Models & schema generation**: Lucid ORM models live in `app/models/`. `backend/database/schema.ts` is **auto-generated** from migrations (`node ace migration:run` regenerates it) — never hand-edit; it defines base `*Schema` classes that models `compose()` with mixins like `withAuthFinder`. `backend/database/schema_rules.ts` lets you customize schema generation per-column.
- **Validation**: request validators use VineJS (`@vinejs/vine`), defined in `app/validators/*.ts` and consumed via `request.validateUsing(...)` in controllers.
- **Serialization**: controllers call `ctx.serialize(data)` / `ctx.serialize.withoutWrapping(data)` — a custom `HttpContext` extension registered in `backend/providers/api_provider.ts`. It wraps all responses in `{ data: ... }` (except when using `withoutWrapping`) and validates Lucid pagination metadata shape. Model-to-JSON shaping goes through `app/transformers/*.ts` classes extending `BaseTransformer`, which `.pick()` allowed fields (see `UserTransformer`) — always transform models before serializing, don't return raw model instances.
- **Database**: SQLite file at `backend/tmp/db.sqlite3` (gitignored, regenerated by migrations). Migrations live in `backend/database/migrations/`, timestamp-prefixed. To change the schema: add a migration, run `node ace migration:run`, which regenerates `database/schema.ts`.
- **Tuyau**: `@tuyau/core` generates a typed route/controller registry (`generateRegistry()` hook in `adonisrc.ts`, output under `.adonisjs/`) used both for route wiring (`#generated/controllers`) and for typed API client generation potentially consumed by the frontend later.

### Frontend

Bare Vite + React 19 + TypeScript scaffold — no router, state management, or API client has been added yet. When building features here, there are no existing conventions to follow yet; check with the user on preferred libraries (routing, data fetching, styling) before introducing new dependencies.

### Cross-cutting

- CORS origins are configured via `CORS_ORIGIN` env var in `backend/.env` (commented out by default in `.env.example`); must include the frontend's dev origin (`http://localhost:5173`) for the frontend to call the API.

## Reglas de proceso

- Antes de tocar código: crear una rama nueva (`git checkout -b feat/<slug>`). Nunca commitear directo en `main` o `s1/start`.
- Al cerrar la tarea: usar la skill `/commit`, luego `gh pr create` con una descripción completa de los cambios en el cuerpo del PR.
- Después de abrir el PR: usar el subagente `adversarial-reviewer` sobre él antes de darlo por terminado.
- No repitas ese resumen en el chat: la sesión se va a perder, el PR no. Responde solo con la URL del PR.
